## Контрольные вопросы
1. Почему второй dotnet build может быть быстрее первого? 
2. Почему удаление bin и удаление obj — не одно и то же с точки зрения последствий 
для сборки? 
3. Что изменится, если bin и obj не сохранять на диске между запусками? 
4. Зачем системе сборки нужен .csproj, если весь код — в Program.cs? 
5. Почему изменение одного исходного файла не обязательно означает полную 
сборку всего проекта? 
6. Почему bin и obj обычно не хранят в Git (вспомните .gitignore из прошлого 
занятия)?

## Ответы 
1. Второй запуск происходит быстрее благодаря инкрементальной сборке.
2. Удаление bin удаляет только конечный результат (исполняемый файл). Удаление obj гораздо серьезнее — оно удаляет все промежуточные данные, метаданные и информацию о зависимостях.
3. Каждая сборка будет проходить медленнее, так как компиляция и загрузка зависимостей будут запускаться с нуля.
4. Это конфигурация проекта: в нём указаны версия .NET, подключаемые библиотеки.
5. Компилятор собирает только изменённый файл и связывает его с уже готовыми файлами из кеша.
6. Это временные и «тяжёлые» файлы, которые автоматически создаются при сборке на любом компьютере.
