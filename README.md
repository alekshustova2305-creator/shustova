## Лабораторная работа №1 (Контрольные вопросы)

 1. Чем dotnet run отличается от dotnet build? Какая команда что делает?  
 2. Какие файлы появляются в bin/Debug/net10.0/ после сборки? Что в них лежит? 
Зачем нужен .pdb?
 3. Что делает компилятор с вашим .cs-файлом перед запуском? Почему процессор 
не может выполнить текст исходного кода напрямую?
 4. Зачем нужен .gitignore? Что произойдёт, если положить в репозиторий папку 
bin/?
 5. Какой тип данных (int, string, double, bool) вы бы выбрали для хранения: 
фамилии; возраста; среднего балла; признака «студент отчислен / не отчислен»?
 6. Что выведет Environment.ProcessorCount на вашем компьютере? А на ноутбуке 
соседа? Почему цифры могут отличаться?
 7. Зачем вызывать Console.ResetColor() после смены цвета?

 ## Ответы

 1. dotnet build — просто собирает программу (переводит ваш код в файлы).  
   dotnet run — собирает и сразу запускает программу
 2. - .dll — сама программа в промежуточном коде  
   - .exe — чтобы запустить программу в Windows  
   - .pdb — служебный файл для отладки (помогает найти ошибки)  
     .pdb нужен, чтобы Visual Studio показывала номера строк при ошибках и можно было ставить точки остановки.
 3. Он превращает ваш текст в другой код (IL-код), который понимает .NET.  
 4. Это список файлов, которые Git будет игнорировать (не добавлять в репозиторий).  
 5. - фамилия → string
   - возраст → int  
   - средний балл → double 
   - отчислен / не отчислен → bool
 6. Количество логических ядер процессора. У разных компьютеров цифры разные, потому что у них разные процессоры.
 7. Чтобы вернуть обычный цвет текста после того, как мы его поменяли.
